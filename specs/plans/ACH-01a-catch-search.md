# План: ACH-01a — поиск рыбы на экране добавления улова

**Статус:** реализовано 2026-11-22 (каталог ACH-01, Android-слой, экран улова). Unit- и Compose-тесты, `:app:assembleDebug` — зелёные.

## Обзор

Экран `CatchEditScreen` сейчас состоит из `TopAppBar` с заголовком «Пойманная рыба»,
отдельного `OutlinedTextField` для названия рыбы, семи захардкоженных чипов и списка
«Добавлено». По макету заголовок убирается: в app bar постоянно живёт `SearchBar`,
который по тапу разворачивается в полноэкранный поиск; выбор результата или кнопка `+`
(свободный ввод) добавляет рыбу и возвращает на экран с «Добавлено».

Каталог рыб — общий с системой достижений (`ACH-01`): постоянные ID, канонические имена,
алиасы, признак популярности и правила нормализации названий. Свободный ввод сохраняется,
неизвестная рыба учитывается по нормализованному имени.

- Figma: <https://www.figma.com/design/52j3R3JlHFbOCGGv8uRPIR/Fishing-Journal?node-id=4254-8315>
  (фреймы: Empty, Search Focused, Search Results, Fish Added, Total Weight Entered).
- Задача в плане: [docs/to-do.md](../../docs/to-do.md) — `ACH-01a`.

## Цели

1. Ввести контракт каталога рыб и локальный кэш/сид, пригодный для поиска и для достижений.
2. Заменить отдельный инпут названия на постоянный `SearchBar` в app bar + full-screen поиск.
3. Показывать «Недавно добавляли» (до 3) либо «Популярные виды» при пустой истории, и «Результат поиска» без лимита.
4. Поддержать свободный ввод через `+` (рыба вне каталога).
5. Показывать состояние «Уже в списке» (subtitle в error-цвете) и не добавлять дубликат.
6. Собирать чипы обычного режима из истории/популярных (до 10) с сортировкой по числу отчётов.
7. Вынести нормализацию и поиск в чистые функции, покрыть тестами.

## Scope

- **Внутри:** каталог (модель, контракт, сид, Room-кэш), провайдер истории и популярных, поиск,
  два режима экрана, общий `SearchInputField`, состояние в `CreateReportViewModel`, тесты.
- **Вне:** каталог водоёмов (`ACH-08`), серверная выдача наград (`ACH-03`), изменение схемы
  публикации отчёта и таблицы Supabase под `speciesId` (уходит в `ACH-01`/`ACH-02`).
  До этого отчёт по-прежнему публикует `name`; `speciesId` добавляется отдельным шагом.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Recents в поиске | до 3 позиций |
| Результаты поиска | все совпадения, без пагинации и «показать ещё» |
| Чипы обычного режима | до 10 позиций, из истории, иначе популярные |
| Порядок в истории | число отчётов, в которых есть вид (не суммарное количество рыб), затем свежесть |
| Глобальная частота | вне этого плана: отдельная задача `ACH-09`, после появления `speciesId` |
| Пустая история | отдельный список популярных видов (в поиске — до 3, в чипах — до 10) |
| Выбор уже добавленной рыбы | не добавлять повторно; subtitle «Уже в списке» в error-цвете |
| Свободный ввод | `+` в полноэкранном поиске активен при непустом запросе |
| После выбора/`+` | поиск закрывается, возврат на экран с «Добавлено» |
| Back в поиске | закрывает поиск, экран не покидает |
| `✓` сохранения | скрыт в поиске, активен при непустом списке на обычном экране |
| Ограничение веса | 70 кг остаётся временным продуктовым ограничением |

## Состояние экрана

`CatchEditScreen` имеет два взаимоисключающих режима:

| | Обычный | Поиск (full-screen) |
|---|---|---|
| App bar | `←` + свёрнутый `SearchBar` + `✓` | поле с `←` внутри и `+` справа, `✓` нет |
| Тело | чипы, «Общий вес», «Добавлено» | «Недавно добавляли»/«Популярные виды» + «Результат поиска» |
| Ввод | нет | фокус и клавиатура при открытии |
| Выход | назад по экрану | `←`, системный back → обычный режим |

Переходы: тап по `SearchBar` → поиск; выбор результата или `+` → добавить рыбу и закрыть поиск;
`←`/back → закрыть поиск без изменений. В режиме `isTrophy` (`HAUL`) добавление заменяет
предыдущую рыбу; единственная добавленная рыба тоже получает состояние «Уже в списке».

## Данные и контракт каталога

**`FishSpecies`** (домен + Room + будущий Supabase):

- `id` — стабильный строковый идентификатор вида (не UUID записи улова);
- `canonicalName` — отображаемое имя («Щука»);
- `aliases` — варианты написания и падежи для поиска и сопоставления;
- `isPopular` — попадание в fallback-список;
- `sortOrder` — порядок популярных и стабильная сортировка.

**Нормализация** (общая с достижениями, `ACH-01`): trim, схлопывание пробелов,
`lowercase(Locale.ROOT)`, `ё → е`. Пустая строка отбрасывается.

**Сопоставление:** точное совпадение имени/алиаса → `startsWith` → `contains`;
ранжирование по типу совпадения, затем по `sortOrder`/алфавиту; дедупликация по `id`.
Свободно введённые названия сопоставляются по нормализованному имени.

**Источники списков:**

- **recents** — имена рыб из собственных отчётов пользователя (`reportDetailsDao.getHomeReports(userId)`
  через `FishingRepository.getHomeReports`, только свои, не избранные чужие). Уникальные по
  нормализованному имени; порядок: **число отчётов с видом** по убыванию, затем свежесть;
  лимит 3. Считается именно количество отчётов, а не суммарный улов: один отчёт на 200 карасей
  не должен перевешивать 20 отчётов с карасём.
- **popular** — `isPopular = true`, `sortOrder`; лимит 10 для чипов и 3 для поиска.
- Частота считается по закэшированным отчётам пользователя (страница 20 + догруженные);
  SQL-агрегация недоступна, пока рыба хранится в `fishJson`. Глобальная частота по всем
  пользователям — вне этого плана (`ACH-09`).
- Если история пуста, поиск показывает «Популярные виды» вместо «Недавно добавляли»;
  чипы — популярные.

**Свободный ввод:** `+` создаёт `Fish(name = нормализованное отображаемое имя, count = 1)`.
Имя обрезается и ограничивается разумной длиной (например, 50 символов). Дубликат с уже
добавленной рыбой или каталогом не создаётся: строка подсвечивается как «Уже в списке».

## UI

**Обычный режим**

- `TopAppBar`: `←` (48dp), свёрнутый `SearchBar` 56dp / 28dp radius / `surfaceContainerHigh`
  (= `#E8E7EF` в текущей палитре), placeholder «Напишите название рыбы», справа иконка лупы;
  `✓` сохранения, enabled при непустом списке.
- Свёрнутое поле `readOnly`: клик разворачивает поиск, курсор в свёрнутом состоянии не показывается.
- Секция «Рыба, которую вы уже указывали в отчетах»: `FlowRow`, до 10 чипов, выбранный — с `✓`.
- Поле «Общий вес (Необязательно)» и валидация остаются как сейчас.
- «Добавлено»: имя, «N шт.», `[−][+]`, отдельный `✕` для удаления строки.

**Полноэкранный поиск**

- Поле 56dp вверху; `←` внутри поля закрывает поиск; `+` справа активен только при непустом запросе.
- Тело: секция «Недавно добавляли» (3) или «Популярные виды», ниже «Результат поиска».
- Строка: min 48dp, padding 16dp, иконка 24dp (история/каталог), имя `bodyLarge`, subtitle
  «Уже в списке» в `MaterialTheme.colorScheme.error`; для такой строки клик — no-op.
- Список — `LazyColumn`, `imePadding`; скролл не ломается при открытой клавиатуре.
- Секции результатов без лимита; пустой результат — просто отсутствие секции (плюс остаётся доступен).

**Переиспользование:** вынести общий `SearchInputField` из
`LocationSearchScreen.SearchFieldHeader` и `ReportSearchScreen.ReportSearchHeader`
и использовать в трёх местах (обычный, полноэкранный, экраны поиска отчётов/водоёмов).

## Архитектура

- `TextFieldState`/`SearchBarState` создаются на уровне экрана (или ViewModel), а не внутри
  полноэкранного слоя: иначе запрос сбрасывается при закрытии поиска.
- `CreateReportViewModel`: режим, `query`, добавленные рыбы, вес, потоки каталога и recents;
  режим и запрос — в `SavedStateHandle` для переживания process death. `formSelectedFish`
  остаётся контрактом с навигацией.
- Чистые функции без Compose: `normalizeFishName`, `searchFish(query, species, aliases)`,
  `recentsFrom(reports, limit)`, `popularFrom(species, limit)`.
- UI-компоненты: `FishSearchBar` (свёрнутый), `FishSearchView` (полноэкранный),
  `FishSuggestionChips`, `FishAddedRow`, переиспользуемый `SearchInputField`.
- Идентичность рыбы в списке: по `speciesId`, для свободного ввода — по нормализованному имени;
  сравнение также по алиасам каталога.

## Шаги

### Step 1: Контракт каталога, сид и Room-кэш

**Контекст:** `model/Fish.kt`, `data/local/AppDatabase.kt`, `data/local/DatabaseModule.kt`,
`data/FishingRepository.kt`. Источник данных окончательно выбирается в `ACH-01`; здесь
фиксируется контракт и временный сид, чтобы разблокировать UI.

**Действия:**
1. Добавить домен `FishSpecies(id, canonicalName, aliases, isPopular, sortOrder)`.
2. Ввести `FishCatalogRepository` с наблюдением каталога и популярных; реализации —
   Room + сид (Supabase подключается в `ACH-01`/`ACH-02` без изменения UI).
3. Room: таблица `fish_species` + DAO, регистрация в `AppDatabase` (destructive migration уже настроена).
4. Сид: пресноводные виды Беларуси и соседних водоёмов с алиасами; популярные помечены.

**Критерии:**
- [ ] Каталог читается из Room, сид применяется при первом запуске.
- [ ] Популярные отдаются в стабильном порядке.
- [ ] Интерфейс не зависит от конкретного источника (Room/Supabase).

**Зависимости:** контракт — от `ACH-01`, но шаг можно начинать на сиде.

### Step 2: Нормализация и поиск

**Действия:**
1. `normalizeFishName`: trim, пробелы, lowercase(ROOT), `ё→е`.
2. `searchFish`: точное совпадение → prefix → contains, дедупликация по `id`, ранжирование.
3. Сопоставление свободного ввода с каталогом по имени и алиасам; `isAlreadyAdded` по
   `speciesId` либо нормализованному имени.

**Критерии:**
- [ ] «щук» находит «Щука», регистр и `ё/е` не влияют.
- [ ] Дубликаты не появляются в результатах.
- [ ] Функции чистые и покрыты unit-тестами.

**Зависимости:** Step 1.

### Step 3: История и популярные

**Действия:**
1. `recentsFrom`: собрать имена рыб из собственных отчётов, нормализовать, unique, сортировка
   число отчётов (убывание) → свежесть, лимит 3.
2. `popularFrom`: `isPopular`, лимит 10 (чипы) / 3 (поиск).
3. Пробросить в `CreateReportViewModel` (у него есть `FishingRepository` и `AuthRepository`).
   Не использовать избранные чужие отчёты как источник истории.

**Критерии:**
- [ ] Recents ограничены 3 и обновляются после сохранения отчёта.
- [ ] Повторные отчёты с тем же видом повышают его в истории; количество рыб внутри отчёта не влияет.
- [ ] Без истории UI получает популярные.
- [ ] Чипы не превышают 10.

**Зависимости:** Step 1, Step 2.

## Риски и снижение

- **Каталог ещё не выбран (`ACH-01`).** Контракт + сид + Room-кэш; замена источника не трогает UI.
- **`speciesId` пока не публикуется в отчёте.** Достижения продолжают считать по нормализованному
  имени; добавление ID в payload согласуется с `ACH-02`/`ACH-03`.
- **Сброс запроса при закрытии поиска.** `TextFieldState` hoist-ится выше полноэкранного слоя.
- **Recents из кэша первой страницы.** Частота считается по загруженным отчётам (страница 20 +
  догруженные), в памяти из `fishJson`; при пустом кэше работает fallback на популярные.
  Глобальная частота — отдельная задача `ACH-09`.
- **Смешение избранных чужих отчётов.** История строится только по собственным отчётам.
- **Рост списка чипов.** Лимит 10 и `FlowRow`; проверка на малых экранах и в ландшафте.
- **Дубликаты из-за написания.** Сравнение по `speciesId`, имени и алиасам после нормализации.

## Открытые вопросы
